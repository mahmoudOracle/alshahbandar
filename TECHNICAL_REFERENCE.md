## i18n Implementation Guide

### Adding New i18n Keys

**Pattern:** `{feature}{Component}{Element}`

**Examples:**
```typescript
// Format: featureName: 'Arabic Text',
invoiceDetailTitle: 'فاتورة',
invoiceDetailCustomerLabel: 'العميل',
expenseCategoryNew: 'فئة مصروفات جديدة',
collectionPageTitle: 'التحصيل اليومي',
```

### Using i18n in Components

**Simple Text:**
```typescript
import { t } from '../src/i18n/t'

<h1>{t('invoiceDetailTitle')}</h1>
<label>{t('invoiceDetailCustomerLabel')}</label>
```

**With Parameters:**
```typescript
// In ar.ts:
invoiceDetailTax: 'الضريبة ({rate}%)',
invoiceDetailEmailSubject: 'فاتورة #{invoiceNumber} من {businessName}',

// In component:
<div>{t('invoiceDetailTax', { rate: 15 })}</div>
// Output: "الضريبة (15%)"

const subject = t('invoiceDetailEmailSubject', {
  invoiceNumber: 'INV-001',
  businessName: 'شركة النور'
})
// Output: "فاتورة #INV-001 من شركة النور"
```

### i18n Keys Checklist

When implementing new features:

- [ ] All user-facing text added to `src/i18n/ar.ts`
- [ ] Key naming follows `{feature}{Component}{Element}` pattern
- [ ] All parameters clearly named in key text
- [ ] Component imports `t` function: `import { t } from '../src/i18n/t'`
- [ ] All text in JSX uses `t()` function
- [ ] No hardcoded Arabic strings in components
- [ ] Notifications use i18n keys
- [ ] Dialog confirmations use i18n keys
- [ ] Error messages use i18n keys

## Firestore Data Models

### Collection: expenseCategories

**Path:** `companies/{companyId}/expenseCategories/{categoryId}`

**Document Structure:**
```typescript
{
  id: string              // Auto-generated by Firebase
  name: string           // "الإيجار", "المرافق", "الرواتب"
  isActive: boolean      // true = visible in dropdowns
  createdAt: Timestamp   // serverTimestamp()
  companyId: string      // For data integrity verification
}
```

**Query Example:**
```typescript
// Get active categories only
const q = query(
  collection(db, `companies/${companyId}/expenseCategories`),
  where('isActive', '==', true),
  orderBy('name', 'asc')
)
const snap = await getDocs(q)
const categories = snap.docs.map(doc => ({
  id: doc.id,
  ...doc.data()
}))
```

**Write Example:**
```typescript
// Add new category
const ref = collection(db, `companies/${companyId}/expenseCategories`)
const docRef = await addDoc(ref, {
  name: 'إيجار مكتب',
  isActive: true,
  companyId: companyId,
  createdAt: serverTimestamp()

```

### Collection: receipts

**Path:** `companies/{companyId}/receipts/{receiptId}`

**Document Structure:**
```typescript
{
  id: string              // Auto-generated
  companyId: string       // Safety: include company ID
  customerId: string      // Reference to customer document
  customerName: string    // Denormalized for display
  amount: number         // 1250.50
  date: string          // ISO 8601 format: "2026-02-04"
  method: string        // "cash" | "transfer" | "check" | "wallet" | "other"
  note?: string         // Optional: "دفعة شهرية" 
  createdAt: Timestamp   // serverTimestamp()
}
```

**Query Examples:**
```typescript
// Get receipts by date
const startDate = '2026-02-04'
const endDate = '2026-02-04'

const q = query(
  collection(db, `companies/${companyId}/receipts`),
  where('date', '>=', startDate),
  where('date', '<=', endDate),
  orderBy('date', 'desc')
)
const snap = await getDocs(q)

// Calculate totals
const receipts = snap.docs.map(doc => doc.data())
const cashTotal = receipts
  .filter(r => r.method === 'cash')
  .reduce((sum, r) => sum + r.amount, 0)

const nonCashTotal = receipts
  .filter(r => r.method !== 'cash')
  .reduce((sum, r) => sum + r.amount, 0)
```

## Security & CompanyId Scoping

### Multi-Tenant Security Model

**Every query MUST include companyId verification:**

✅ **Correct - Scoped Query:**
```typescript
const q = query(
  collection(db, `companies/${companyId}/subcollection`),
  where('field', '==', value)
)
const snap = await getDocs(q)
```

❌ **Wrong - Missing CompanyId Check:**
```typescript
// This is a security vulnerability!
const q = query(
  collection(db, 'globalCollection'),
  where('field', '==', value)
)
```

### Firestore Security Rules

**Required Rules (firestore.rules):**

```
service cloud.firestore {
  match /databases/{database}/documents {
    // Deny by default
    match /{document=**} {
      allow read, write: if false;
    }

    // Companies
    match /companies/{companyId} {
      allow read, write: if request.auth.uid != null 
        && isOwner(companyId);
      
      // Expense Categories - Read/Write scoped by company
      match /expenseCategories/{categoryId} {
        allow read, write: if request.auth.uid != null 
          && isOwner(companyId)
          && resource.data.companyId == companyId;
      }
      
      // Receipts - Read/Write scoped by company
      match /receipts/{receiptId} {
        allow read, write: if request.auth.uid != null 
          && isOwner(companyId)
          && resource.data.companyId == companyId;
      }
    }

    // Helper functions
    function isOwner(companyId) {
      return get(/databases/$(database)/documents/companies/$(companyId)/users/$(request.auth.uid)).data.role != null;
    }
  }
}
```

### CompanyId Injection Points

When saving data to Firestore, **always include companyId**:

## Troubleshooting Guide

### Issue: Hardcoded Arabic Text Appears

**Solution:**
1. Check component file doesn't have literal Arabic strings
2. Verify i18n key exists in `src/i18n/ar.ts`
3. Verify component imports `t()` function
4. Verify JSX uses `t('keyName')` pattern
5. Run: `grep -r "[\u0600-\u06FF]" src/pages/` to find Arabic text

### Issue: Categories Not Loading in ExpenseForm

**Solution:**
1. Verify Firestore collection exists: `companies/{companyId}/expenseCategories`
2. Check browser console for errors
3. Verify Firebase Auth user is logged in
4. Verify `getExpenseCategories()` returns data
5. Add console.log to debug: `console.log('Categories:', categories)`

### Issue: DailyCollection Totals Incorrect

**Solution:**
1. Verify receipt data has `method` field set correctly
2. Check totals calculation: filter on exact string match (`'cash'` not `'Cash'`)
3. Verify dates are ISO format: `"2026-02-04"`
4. Check Firestore data types (amount should be number, not string)

### Issue: Cross-Company Data Leakage

**Solution:**
1. Audit all queries in data service
2. Verify each query includes companyId path: `companies/${companyId}`
3. Check Firestore security rules are deployed correctly
4. Run: `firebase firestore:delete --project production-id` (if needed)
5. Re-deploy security rules: `firebase deploy --only firestore:rules`
